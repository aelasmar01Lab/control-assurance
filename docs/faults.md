Generated by `cca faults` from the fault list and retry policies in `internal/assurance`. Do not edit by hand.

Every fault below is injected into a synthetic source by `TestEveryFault`, which asserts the error class or result shown here and that the fault never produces a `pass`. All data in those tests is synthetic.

## Retry policy by error class

Each attempt, including each retry, is its own collection run row.

| Error class | Retry | Why |
| --- | --- | --- |
| `auth` | Not retried. The next scheduled collection tries again. | A missing, invalid or expired credential stays that way until someone replaces it. |
| `permission` | Not retried. The next scheduled collection tries again. | A refusal stays a refusal until someone changes the grant. |
| `rate_limited` | Up to 4 attempts; waits: 15 min, 15 min, 15 min. The source's own Retry-After is used instead when it gives one, capped at 1 h. | Wait as long as the source asks, up to an hour, or 15 minutes when it does not say. |
| `not_found` | Not retried. The next scheduled collection tries again. | The resource is missing or hidden; asking again does not change that. |
| `network` | Up to 4 attempts; waits: 1 min, 5 min, 25 min. | Connection failures and timeouts are usually brief. |
| `server` | Up to 4 attempts; waits: 1 min, 5 min, 25 min. | A fault on the source's side is usually brief. |
| `malformed_response` | Up to 2 attempts; waits: 5 min. | One more attempt covers a response cut short; a lasting change of format needs a code change. |
| `unexpected_status` | Not retried. The next scheduled collection tries again. | The cause is not understood, so repeating the request is not known to be safe or useful. |
| `storage` | Up to 2 attempts; waits: 1 min. | One more attempt covers a brief fault in the evidence store. |
| `interrupted` | Up to 3 attempts; waits: at once, at once. | The worker stopped; the source was not at fault, so the next worker tries at once. |
