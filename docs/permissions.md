# Permission matrix

Generated by `cca permissions` from `internal/authz`. Do not edit by hand.

Every entry point (web pages, CLI commands, exports and jobs) reaches data through the service layer, which calls one function, `authz.Can`, before it acts.

| Action | operator | control_owner | reviewer | auditor |
| --- | --- | --- | --- | --- |
| `view` | allow | allow | allow | allow |
| `export` | allow | allow | allow | allow |
| `collection.run` | allow | deny | deny | deny |
| `evaluation.run` | allow | deny | deny | deny |
| `catalog.load` | allow | deny | deny | deny |
| `evidence.submit` | allow | allow | deny | deny |
| `evidence.review` | deny | deny | allow | deny |
| `exception.request` | allow | allow | allow | deny |
| `exception.decide` | deny | deny | allow | deny |
| `remediation.note` | allow | allow | deny | deny |

Rules that depend on the item, applied after the table:

- A control owner may submit evidence, request an exception or add a remediation note only for a control they own.
- Nobody may review evidence they submitted or decide an exception they requested. The database enforces the same rule with a constraint.
- A request with no signed-in, known user is denied everything.
