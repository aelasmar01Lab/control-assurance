# Check guide

Generated by `cca checks guide` from the check definitions in `internal/check`. Do not edit by hand.

A check result is one of `pass`, `fail` or `not_evaluated`. A collection failure is none of these: it is recorded on the collection run and produces no result.

## AWS-01 (version 1)

| | |
| --- | --- |
| Assertion | Every IAM user with a console password has MFA, and so does the root user. |
| Evidence source | AWS IAM: the credential report (`GenerateCredentialReport`, `GetCredentialReport`) and `GetAccountSummary` |
| Read permission | `iam:GenerateCredentialReport`, `iam:GetCredentialReport`, `iam:GetAccountSummary` |
| A pass establishes | The MFA state of IAM users and of root when the credential report was generated. |
| A pass does not establish | Anything about federated or IAM Identity Center users, or the strength of the factor. |
| Internal control | Human access |
| Framework mapping | MVSP 4.2, partial. |

## GH-01 (version 1)

| | |
| --- | --- |
| Assertion | An active rule on the default branch requires at least one approving review. |
| Evidence source | GitHub REST: `GET /repos/{owner}/{repo}/rules/branches/{branch}` (active rules only), plus the repository and branch records |
| Read permission | Repository metadata: read |
| A pass establishes | The rule was active on that branch at collection time. |
| A pass does not establish | That past changes were reviewed, who may bypass the rule, or anything about classic branch protection. |
| Internal control | Change management |
| Framework mapping | MVSP 3.5, supporting. Required review is not an MVSP requirement; it supports the internal control. |

## GH-03 (version 1)

| | |
| --- | --- |
| Assertion | No open Dependabot alert of medium severity or higher is older than its patch deadline: 30 days for high and critical, 90 days for medium. |
| Evidence source | GitHub REST: `GET /repos/{owner}/{repo}/dependabot/alerts?state=open` |
| Read permission | Dependabot alerts: read |
| A pass establishes | Every open alert visible to the credential was within its deadline at collection time. |
| A pass does not establish | Anything about vulnerabilities Dependabot does not know about, dismissed alerts, or low severity alerts. When alerts are turned off the result is not evaluated, never a count of zero. |
| Internal control | Dependency remediation |
| Framework mapping | MVSP 2.6 and 3.4, partial. The deadlines are a policy choice; MVSP 3.4 sets 90 days for application vulnerabilities. |

## GH-04 (version 1)

| | |
| --- | --- |
| Assertion | The repository publishes a security policy file at a standard path on its default branch. |
| Evidence source | GitHub REST: `GET /repos/{owner}/{repo}/contents/{path}` for `SECURITY.md`, `.github/SECURITY.md` and `docs/SECURITY.md` |
| Read permission | Repository contents: read |
| A pass establishes | A non-empty policy file existed at a standard path at collection time. |
| A pass does not establish | Anything about the file's content, any safe-harbour wording, or that reports are triaged. A default policy inherited from an organisation's `.github` repository is not read. |
| Internal control | Vulnerability disclosure |
| Framework mapping | MVSP 1.1, partial. |
