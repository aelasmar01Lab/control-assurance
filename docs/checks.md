# Check guide

Generated by `cca checks guide` from the check definitions in `internal/check`. Do not edit by hand.

A check result is one of `pass`, `fail` or `not_evaluated`. A collection failure is none of these: it is recorded on the collection run and produces no result.

## GH-01 (version 1)

| | |
| --- | --- |
| Assertion | An active rule on the default branch requires at least one approving review. |
| Evidence source | GitHub REST: `GET /repos/{owner}/{repo}/rules/branches/{branch}` (active rules only), plus the repository and branch records |
| Read permission | Repository metadata: read |
| A pass establishes | The rule was active on that branch at collection time. |
| A pass does not establish | That past changes were reviewed, who may bypass the rule, or anything about classic branch protection. |
| Internal control | Change management |
| Framework mapping | MVSP 3.5, supporting. Required review is not an MVSP requirement; it supports the internal control. |

## GH-02 (version 1)

| | |
| --- | --- |
| Assertion | An active rule on the default branch requires named status checks. |
| Evidence source | GitHub REST: `GET /repos/{owner}/{repo}/rules/branches/{branch}` (active rules only), plus the repository and branch records |
| Read permission | Repository metadata: read |
| A pass establishes | Named checks must pass before merge, as of collection time. |
| A pass does not establish | That those checks test anything meaningful, or who may bypass the rule. |
| Internal control | Change management |
| Framework mapping | MVSP 3.5, supporting. |
