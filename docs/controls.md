# Control and mapping guide

Generated by `cca controls guide` from the files under `controls/`, `mappings/`, `tracking/` and `scope/`. Do not edit by hand; edit those files and run `make content`.

Controls, mappings and tracking entries are drafted by an AI agent and reviewed by the maintainer. Each is a **draft, not reviewed** until the maintainer signs it, and says so here. Nothing here has been reviewed by an auditor.

A control is something a small company does to reduce a risk. It is written for a generic company, not for one organization. A check is one narrow assertion over collected evidence (see the [check guide](checks.md)). A mapping ties a control to a framework requirement and states how strong the tie is:

- **direct**: the control, if supported, is what the requirement asks for. A direct mapping that is still a draft counts as partial.
- **partial**: the control covers part of what the requirement asks for.
- **supporting**: the control is related evidence, and does not establish the requirement.

Reviewed so far: 0 of 27 controls and 0 of 32 mappings.

## How a control's state is derived

The state is worked out on read and never stored. The first match wins:

| State | When |
| --- | --- |
| Not evaluated | No check for the control has produced a result |
| Needs attention | A current failure with no approved, unexpired exception; or manual evidence missing, rejected or awaiting review |
| Stale | The newest evidence is older than the control's window, or accepted manual evidence is past its validity date |
| Accepted risk | Every current failure is covered by an approved, unexpired exception |
| Not evaluated | A check's current result could not be determined |
| Supported | Every check passes on current evidence and manual evidence is accepted and valid |

A collection failure is not an input. It adds no evidence, so the previous results stand and age toward stale.
